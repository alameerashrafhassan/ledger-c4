Ledger reversal

Any posted LedgerTransaction can be inverted. Ledger::RevertTransaction builds a new LedgerTransaction with debit and credit accounts swapped, posts it via the same Ledger::CreateTransaction service, and links the original to the new transaction through reversal_transaction_id.

Actors

  • Initiator: Operator (manual reversal, no controller endpoint observed in repo — typically invoked via console / admin task)
  • Affected: The two accounts on the original transaction
  • System: Ledger::RevertTransaction

After reversal, the two accounts are back to their pre-original positions; both the original and the reversal remain in the ledger as posted entries.

Pre-conditions

  • Original LedgerTransaction.status == posted
  • Original has at least one debit and one credit entry
  • Caller has access to the original transaction's id (typically operator via console)

Post-conditions

  • A new LedgerTransaction with status posted exists
  • original.reversal_transaction_id points at the new transaction
  • Account balances on both ends are restored

Reconciliation impact

  • Both rows remain visible. Net effect on each account is zero.
  • The reversal_transaction_id link is the canonical signal that a transaction was reversed; reports filtering by this exclude reversed pairs.
