Purpose

Shows the card-creation worker and how the same job dispatches to three CMS-specific creation managers, including the EBC bulk-cluster path that doesn't behave like PTL or Postilion.

Decisions & Notes

  • EBC differs in shape. Cards are pre-issued; creation = association. The job stays uniform because the difference is hidden inside Ebc::Cards::CreationManager.
  • Job is idempotent through state. Retries check CardsRequest state to avoid duplicate cards on the CMS side.
  • EBC HTTP only via CDE. The EBC manager calls HttpClients::Ebc which is wired only to the CDE base URI.

Assumptions

  • Job name CardCreationJob is the canonical naming pattern; verify against app/jobs/cards/ if it differs.
  • Reissue / block jobs follow the same template and are not redrawn here.
