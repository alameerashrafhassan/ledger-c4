Ledger transaction statuses (LedgerTransaction::STATUSES)

StatusMeaning
pendingDefault after create!; entries not yet posted.
postedBoth entries posted and balances updated.
failureValidation failed; transaction_errors populated.
voidReserved status; not actively written by the documented flows.

Ledger entry statuses (LedgerEntry::STATUSES)

StatusMeaning
pendingDefault; created via ledger_entries.pending.create! before balance update.
postedAfter PostBalanceUpdate succeeds.
archivedSoft-archive state for historical entries.

Ledger entry directions (LedgerEntry::DIRECTIONS)

debitDecreases the source side. debit_first scope orders by direction desc.
creditIncreases the destination side. credit_first scope orders by direction asc.

Disbursement statuses

Tracked on Disbursement and EmployeeDisbursement.

StatusWhereMeaning
approvedDisbursementPre-condition: Disbursement.approved.find in Processor.
in_progressDisbursementSet under with_lock; second worker raises UNIQUENESS_ERROR.
completedDisbursement / EmployeeDisbursementAll employees paid (or one employee paid).
failedDisbursement / EmployeeDisbursementAny employee failed (cycle) or specific transfer failed (per-employee).

Chargeback statuses

StatusMeaning
pendingInitial state; only this can transition to settled.
approvedParam value passed in to trigger settlement.
completedSettlement ledger transaction posted.
failedSettlement ledger transaction failed.

Key services

ServiceRole
Ledger::CreateTransactionThe single entry point for posting a balanced transaction.
Ledger::RevertTransactionInverts a posted transaction by calling CreateTransaction with from/to swapped.
Ledger::Transactions::ValidatorValidates a pending transaction against from/to before entries are posted.
Ledger::UpdateLocalAccountUpdates accounts.posted_balance_cents for a given entry.
Ledger::PostBalanceUpdateDrives the balance-update step; can include CMS-side updates via process_by.

Other terms

referrerPolymorphic association on LedgerTransaction — usually the domain object that caused the transaction (Disbursement, EmployeeDisbursement, Chargeback). Optional.
reversal_transactionSelf-association on LedgerTransaction: original.reversal_transaction = the inverted transaction.
trx_uuidUnique transaction identifier on LedgerTransaction; the database constraint that prevents duplicate posts.
posted vs available balanceBoth are tracked on Account as posted_balance_cents and available_balance_cents; the documented flows update posted_balance_cents via UpdateLocalAccount.
system_account?global_cash, cashback, or suspense. No accountable.
local?cash or global_cash.
