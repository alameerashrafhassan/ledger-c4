C4 Level 3 — Components inside the Rails API

Controllers, the auth/policy layer, and supporting service entry points that make up the Rails API container.
Component External System Cylinder = data store Dashed border = container boundary

Purpose

Decomposes the Rails API container into its main components: the controller layer (one block per major resource group), the auth/authorization layer, and the service entry into ProcessorMediator. Useful for engineers picking up a feature and needing to know where the seam lives.

Decisions & Notes

  • One choke-point for auth. ApplicationController enforces authenticate and check_payment_provider!; subclasses don't repeat this. New controllers must inherit, not skip these callbacks.
  • Controllers stay thin. They route into domain services and never call CMS adapters directly — that's the mediator's job.
  • Pundit per resource. Each controller has a matching policy in app/policies; missing a policy is a deliberate decision, not an oversight.

Assumptions

  • Controllers shown are the major resource groupings; minor controllers (e.g. card_operations, transaction_alerts) are folded into the larger blocks for readability.
  • The component diagram glosses over serializers / decorators; if those become a hot architectural surface they should be promoted into their own component.
