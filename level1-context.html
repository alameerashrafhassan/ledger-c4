Purpose

This level shows PayEngine 2.0 as a single black box and the people and external systems it interacts with. It is the highest-level view, intended for stakeholders who need to understand scope and integrations, not internals.

Decisions & Notes

  • Three CMS providers behind one façade. Persons and front-ends never address PTL/Postilion/EBC directly; PayEngine routes via ProcessorMediator using each beneficiary's cms_marker.
  • EBC is not addressed directly. All EBC traffic must go through the CDE proxy application — drawn explicitly so this constraint isn't lost.
  • Liberty front-ends are external to the PayEngine system boundary; PayEngine ships an API only, not UI.
  • Auth is a separate system (dopay-conductor), not embedded — the same gem powers other dopay services.

Assumptions

  • The Liberty web/mobile apps are the only first-party callers of the API today; partner direct integration would warrant adding a node.
  • Mailchimp Transactional is the sole transactional email provider in use.
  • Bank file exchange is shown as a single external node; in reality there are multiple banks per tenant.
