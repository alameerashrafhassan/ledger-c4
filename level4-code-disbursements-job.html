Purpose

Shows what runs when an approved disbursement is executed asynchronously: the parent DisbursementJob fans out to per-employee jobs, each of which calls ProcessorMediator for CMS-bound balance / wallet operations.

Decisions & Notes

  • Fan-out, not in-line. The parent job enqueues per-employee jobs so a single failed CMS call can't fail the whole batch.
  • Retry-aware service variant. protected_update_balance intentionally points at PTL's UpdateWithRetry to wrap transient errors — and is kept separate from update_balance so tests don't always pay the retry cost.
  • State transitions land in the model. Job code calls a transition helper; it doesn't write status fields by hand.

Assumptions

  • Queue name :disbursements shown as the convention; verify against config/sidekiq.yml for the production queue name.
  • Notifications are illustrative; the actual job may use a dedicated NotificationsJob.
